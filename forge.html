More About Forge

Forge brings human engineers and specialist AI agents into one project environment, with the context, skills and controls needed to work as a coordinated team.

Overview

AI assistance is often fragmented across software delivery — context, decisions and accountability scattered across separate interactions and tools.

Each interaction starts with limited context. Requirements, architecture and code decisions become separated. Review, approval and accountability often sit outside the AI workflow. What's missing is coordination across people, agents, context and controls.

Forge brings the engineering team into one working environment. Engineers work with specialist AI agents that understand the project, follow defined ways of working, and coordinate when a task spans several roles — directly, one-to-one, or through the optional Forge Project Manager, which involves the relevant specialists and maintains continuity across their contributions.

Shared Project Context & Structured Skills

Forge organises project information into a common working context that agents can access according to their permissions — for consistent interpretation across roles, continuity between specialists, and traceability to source material.

That shared context includes: requirements and project documents, architecture and technical material, source repositories, standards/templates/working instructions, and relevant conversation and task history.

Each skill combines role instructions with the organisation's approved standards, templates and review criteria. As the deck puts it: "The model provides intelligence. The skill applies your way of working."

Human Control & Enterprise Controls

Forge can pause a supported action and request an authorised decision — approve, redirect or reject — before work continues, with the request, response and outcome retained. Human engineering approval remains required before merge and release.

Enterprise controls surround every Forge project at the boundary where agents, information and repositories come together — identity and access, project isolation, security and accountability, and operational visibility.

  • Identity and access — authenticated users and sessions, role and project entitlements
  • Project isolation — files and agents scoped to the project, separate repository credentials
  • Security and accountability — credentials kept outside prompts, all activity recorded
  • Operational visibility — agent and execution-host status, provisioning, trace and health records

Use Case Spotlight — Day-2 Vulnerability Remediation

Financial regulator · DevSecOps application. SonarQube or Nexus IQ identifies a code-quality, security or dependency finding that requires investigation and remediation. Forge workflow: finding analysed → risk and impact assessed → remediation prepared → unit tests generated → independent review → validation completed → pull request prepared, using Jira, GitLab, SonarQube, Nexus IQ and ServiceNow. Human engineering approval remains required before merge and release.

Employee order management system (IT services · internal employee operations): a requested workflow or business-rule change goes through requirement clarified → application impact assessed → change prepared → unit tests prepared → independent review → validation completed → release documentation prepared.

Multi-component defect resolution (enterprise workflow application): a defect affecting several parts of a modular application is worked through expected-behaviour reconstruction, affected-component identification, coordinated investigation, correction, regression-impact validation and release packaging.

End-to-end SDLC delivery (enterprise case-management application): introducing a policy-based, multi-level approval workflow — from requirements and solution design through implementation, independent review, validation and release prepared for human approval.
